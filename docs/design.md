# graftx 設計ドキュメント

## 1. プロジェクト概要

### 一行要約

リポジトリ間のファイル/ディレクトリコピーを加速するTUIツール。

### 解決する課題

新プロジェクトを開始する際、複数のテンプレートリポジトリから設定ファイル等を収集する必要がある。従来はディレクトリを手動で移動し、cpコマンドを都度構成していたが、以下の問題があった：

- ソースとなるリポジトリが複数あり、それぞれへのディレクトリ移動が煩雑
- コピーコマンドのパス構成が面倒でミスしやすい
- 複数リポジトリを渡り歩く際の切替コストが高い

### ユースケース

1. 新プロジェクト開始時に、テンプレートリポジトリA（CI設定）、テンプレートリポジトリB（linter設定）、テンプレートリポジトリC（Dockerfile）からそれぞれ必要なファイルを新プロジェクトにコピーする
2. コピー元リポジトリを `s` キーで素早く切り替えながら、連続してファイルを収集する

### 対象ユーザー

ghqでリポジトリを管理しているCLIユーザー。

### 前提条件

- `ghq` がインストール済みであること
- `fzf` がインストール済みであること

### 技術スタック

- 言語: Go
- TUIライブラリ: jroimartin/gocui

### 操作コンセプト

Vimバインドでキーボードのみで完結できること。キーバインドはyaziのデフォルトキーマップをベースとし、2ペイン構成に合わせた変更を加えている。詳細は「4. キーバインド仕様」を参照。

### 2ペイン構成

- 左ペイン: コピー元（起動時は空。`s`キーで`ghq list | fzf`を発火してリポジトリを選択。頻繁に切替可能）
- 右ペイン: コピー先（起動時にカレントディレクトリを表示。固定）

### コピーの性質

ファイル/ディレクトリをそのまま無加工でコピーする。変換や差分表示は行わない。

### 名前の由来

graftx — 「接ぎ木（graft）」から。複数のソースから必要な部分を取り込んで新しいプロジェクトを育てるイメージ。

## 2. アーキテクチャ

### パッケージ構成

```
graftx/
├── main.go              # エントリポイント
├── internal/
│   ├── ui/              # GUI管理（レイアウト、View生成、キーバインド登録）
│   │   ├── layout.go
│   │   └── keybinding.go
│   ├── pane/            # ペインの状態管理（カーソル位置、選択状態、現在のディレクトリ）
│   │   └── pane.go
│   ├── fs/              # ファイルシステム操作（一覧取得、コピー、削除）
│   │   └── fs.go
│   └── selector/        # ghq + fzf 連携によるリポジトリ選択
│       └── selector.go
├── docs/
│   ├── design.md
│   └── lib/
│       └── gocui.md
└── go.mod
```

### 各パッケージの責務

| パッケージ | 責務 |
|-----------|------|
| `main` | gocui.Guiの初期化、Managerの登録、MainLoopの起動。MainLoopの再起動ループを管理する |
| `internal/ui` | gocui.ManagerインターフェースのLayout実装、View生成・配置、キーバインドの登録。`App`構造体を保持し、アプリケーション全体の状態を管理する。gocuiに直接依存する唯一のパッケージ |
| `internal/pane` | ペインの状態管理。現在のディレクトリパス、エントリ一覧、カーソル位置、選択中ファイル一覧、`YankBuffer`を保持。gocuiに依存しない |
| `internal/fs` | ファイルシステム操作。`FileSystem`インターフェースの定義と実装。ディレクトリのエントリ一覧取得、ファイル/ディレクトリのコピー、削除を提供。`Entry`構造体もここで定義する。gocuiに依存しない |
| `internal/selector` | `ghq list | fzf` の実行とリポジトリパスの取得。`CommandRunner`インターフェースの定義と実装。gocuiに依存しない |

### コンポーネント間の依存関係

```
main
 └── ui
      ├── pane
      │    └── fs
      └── selector
```

- `main` → `ui`: GUIの初期化と起動を委譲
- `ui` → `pane`: ペインの状態を参照・更新し、Viewに描画
- `ui` → `selector`: コピー元リポジトリの選択を委譲
- `pane` → `fs`: ディレクトリ一覧取得やコピー操作を委譲
- `fs`, `selector`, `pane` は `gocui` に依存しない（テスト容易性の確保）

### gocuiとの統合方針

- `ui` パッケージが `gocui.Manager` インターフェースを実装し、`Layout` メソッドでViewの生成・更新を行う
- キーバインドのハンドラは `ui` パッケージ内で定義し、`pane` や `selector` のメソッドを呼び出す
- Viewの更新はgocuiのイベントループ内（Layout関数またはキーバインドコールバック内）でのみ行う

### MainLoopの再起動パターン

gocuiはターミナルを排他的に制御するため、fzfのような対話的な外部プロセスと共存できない。そのため、`main.go`でMainLoopの再起動ループを管理する。

```go
// main.go の概念的な構造
func main() {
    app := ui.NewApp()

    for {
        g, err := gocui.NewGui(gocui.OutputNormal)
        if err != nil {
            log.Fatal(err)
        }

        app.SetGui(g) // Layout・キーバインドを登録

        if err := g.MainLoop(); err != nil && err != gocui.ErrQuit {
            log.Fatal(err)
        }
        g.Close()

        // MainLoop終了理由の判別
        switch app.ExitReason {
        case ui.ExitReasonQuit:
            return // アプリケーション終了
        case ui.ExitReasonSelectRepo:
            // fzfを起動してリポジトリ選択
            repoPath, err := app.Selector.SelectRepository()
            if err == nil && repoPath != "" {
                app.SourcePane.ChangeDir(repoPath)
            }
            app.ExitReason = ui.ExitReasonNone
            // ループ先頭に戻り、gocuiを再初期化
        }
    }
}
```

- `App.ExitReason` フィールドでMainLoop終了理由を判別する（`q`キーによる終了 vs `s`キーによるfzf起動）
- gocui再初期化時、`App`構造体がループをまたいで生存するため、ペインの状態（ディレクトリ、カーソル位置、選択状態）は自動的に復元される
- `Layout`関数が`App`構造体の状態に基づいてViewを再描画するため、追加の復元処理は不要

### エラーハンドリング方針

- 画面下部にステータスバー用のViewを設け、エラーメッセージをユーザーに表示する
- ファイル操作のエラー（権限不足、ディスク容量不足等）はステータスバーに表示し、操作を中断する
- 致命的エラー（gocui初期化失敗等）はプログラムを終了し、標準エラー出力にメッセージを出力する

### テスト方針

| パッケージ | テスト対象 | テスト方法 |
|-----------|-----------|-----------|
| `internal/pane` | カーソル移動、選択状態管理、ディレクトリ遷移 | ユニットテスト。fsパッケージをインターフェースで注入しモック可能にする |
| `internal/fs` | ディレクトリ一覧取得、コピー、削除 | ユニットテスト。一時ディレクトリを使用 |
| `internal/selector` | ghq + fzf の呼び出しとパス解析 | ユニットテスト。コマンド実行をインターフェースで注入しモック可能にする |
| `internal/ui` | gocuiに直接依存するため | テスト対象外（ロジックは他パッケージに委譲済み） |

## 3. UIレイアウト

### 画面全体の構成

```
+----------------------------------+----------------------------------+
|          source (左ペイン)        |        destination (右ペイン)      |
|  Title: ~/src/github.com/user/.. |  Title: ~/projects/myapp          |
+----------------------------------+----------------------------------+
|  > .github/                      |    .gitignore                    |
|    .gitignore                    |    README.md                     |
|  * Dockerfile                    |    src/                          |
|    README.md                     |    go.mod                        |
|    docker-compose.yml            |                                  |
|    src/                          |                                  |
|                                  |                                  |
|                                  |                                  |
+----------------------------------+----------------------------------+
| STATUS: Copied Dockerfile -> ~/projects/myapp/Dockerfile             |
+----------------------------------------------------------------------+
```

- `>` はカーソル位置を示す
- `*` は選択済みファイルを示す
- ペインの幅は左右均等（50:50）

### View一覧

| View名 | 用途 |
|--------|------|
| `source` | 左ペイン。コピー元のファイル一覧を表示 |
| `destination` | 右ペイン。コピー先のファイル一覧を表示 |
| `status` | 画面下部1行。エラーメッセージや操作フィードバックを表示 |

### 左ペイン（コピー元）の表示

- **起動時**: 空。中央に「`s` キーでリポジトリを選択」のようなヒントメッセージを表示
- **リポジトリ選択後**: 選択されたリポジトリのルートディレクトリのエントリ一覧を表示
- タイトルに現在のディレクトリパスを表示

### 右ペイン（コピー先）の表示

- **起動時**: カレントディレクトリのエントリ一覧を表示
- タイトルに現在のディレクトリパスを表示

### ファイルエントリの表示形式

- ファイル名のみ表示（サイズ・更新日時は表示しない）
- ディレクトリは末尾に `/` を付与して区別する（例: `src/`）
- 隠しファイル（`.`で始まるファイル）はデフォルトで表示する
- エントリはディレクトリを先、ファイルを後にソートする。それぞれアルファベット順

### カーソル・選択のハイライト

- カーソル行: gocuiの `Highlight` 機能で背景色を反転して表示
- 選択済みファイル: 行頭に `*` マークを表示

### フォーカス中ペインの視覚的区別

- フォーカス中のペインはgocuiの `SelBgColor` / `SelFgColor` で枠線の色を変更する
- フォーカスしていないペインは通常の枠線色

### ウィンドウリサイズ時の挙動

- Layout関数で毎回 `g.Size()` を取得し、ペイン幅を再計算する
- 左ペイン: `x0=0, x1=maxX/2-1`
- 右ペイン: `x0=maxX/2, x1=maxX-1`
- ステータスバー: `x0=0, x1=maxX-1, y0=maxY-2, y1=maxY`

| キー | yazi | graftx | 理由 |
|------|------|--------|------|
| `s` | 名前で検索 (fd) | コピー元リポジトリ切替 | graftxのコア機能であるリポジトリ切替を優先 |

## 5. コア機能仕様

### 5.1 ファイルブラウジング

- `os.ReadDir` でディレクトリのエントリ一覧を取得する
- ソート順: ディレクトリを先、ファイルを後に配置。それぞれアルファベット昇順
- 隠しファイル（`.`始まり）はデフォルトで表示。`.`キーでトグル
- カーソルは先頭エントリ〜末尾エントリの範囲でクランプする（範囲外に出ない）

### 5.2 ディレクトリ遷移

- `l`キー: カーソル行がディレクトリの場合、そのディレクトリに入る。ファイルの場合は何もしない
- `h`キー: 親ディレクトリへ遷移する。ルートディレクトリの場合は何もしない
- 親ディレクトリに戻った際、直前にいたディレクトリにカーソルを復元する

### 5.3 ファイル/ディレクトリのコピー

コピーは「ヤンク → ペースト」の2ステップで動作する。

**ヤンク (`y`):**
1. 選択中のファイル/ディレクトリがあれば、それらをヤンクバッファに格納
2. 選択がなければ、カーソル行のエントリをヤンクバッファに格納
3. ステータスバーに「N items yanked」と表示

**ペースト (`p`):**
1. ヤンクバッファの各エントリをもう一方のペインの現在のディレクトリにコピー
2. 同名ファイルが存在する場合、確認ダイアログをポップアップペインで表示
3. コピー完了後、コピー先ペインのエントリ一覧をリフレッシュ
4. ステータスバーにコピー結果を表示

**同名ファイル存在時の確認ダイアログ:**
```
+------------------------+
| ファイルが既に存在します  |
| filename.txt           |
|                        |
| [O] 上書き             |
| [R] リネーム           |
| [C] キャンセル          |
+------------------------+
```
- 「上書き」: 既存ファイルを上書き
- 「リネーム」: 新しい名前を入力するポップアップを表示
- 「キャンセル」: そのファイルのコピーをスキップ

**上書きペースト (`P`):**
- 確認ダイアログを表示せず、同名ファイルを強制上書きする

### 5.4 リポジトリ選択

`s`キーでコピー元リポジトリを選択する。

**動作フロー:**
1. gocuiのMainLoopを一時停止する（`gocui.ErrQuit`を返して一旦終了）
2. `ghq list --full-path | fzf` を外部プロセスとして実行し、ターミナルの制御を渡す
3. ユーザーがfzfでリポジトリを選択すると、選択されたパスを取得
4. gocuiを再初期化してMainLoopを再開
5. 左ペインに選択されたリポジトリのルートディレクトリを表示
6. ユーザーがfzfをキャンセルした場合（Esc/Ctrl+C）は、元の状態に戻る

### 5.5 複数ファイル選択とコピー

- `Space`で個別にトグル、`v`でビジュアルモード（範囲選択）、`Ctrl+a`で全選択、`Ctrl+r`で反転
- 選択状態はディレクトリ遷移時にクリアされる
- ヤンク時に選択中のエントリがあれば、それらを優先してヤンクバッファに格納する
- 選択がなければカーソル行のエントリのみをヤンクする

### 5.6 削除操作

**ゴミ箱移動 (`d`):**
- 選択中またはカーソル行のエントリをOS標準のゴミ箱に移動する
  - macOS: `~/.Trash`
- 削除前に確認ダイアログをポップアップペインで表示する
- 削除後、エントリ一覧をリフレッシュ

**完全削除 (`D`):**
- 選択中またはカーソル行のエントリを完全削除（`os.RemoveAll`）する
- 削除前に確認ダイアログをポップアップペインで表示する（「この操作は取り消せません」と警告）
- 削除後、エントリ一覧をリフレッシュ

### 5.7 リネーム

**動作フロー:**
1. `r`キーでポップアップペインを表示
2. 現在のファイル名が初期値として入力欄に表示される
3. ユーザーが新しい名前を入力して`Enter`で確定
4. `Esc`でキャンセル
5. リネーム後、エントリ一覧をリフレッシュ

**ポップアップ表示:**
```
+------------------------+
| リネーム                |
| > filename.txt         |
+------------------------+
```

### 5.8 新規作成

**動作フロー:**
1. `a`キーでポップアップペインを表示
2. ユーザーがファイル名を入力して`Enter`で確定
3. 末尾が`/`の場合はディレクトリを作成、それ以外はファイルを作成
4. `Esc`でキャンセル
5. 作成後、エントリ一覧をリフレッシュ

**ポップアップ表示:**
```
+------------------------+
| 新規作成                |
| > newfile.txt          |
+------------------------+
```

### 5.9 検索・フィルタ

**検索 (`/`, `?`):**
1. キー入力でステータスバーに検索プロンプトを表示（`/pattern`）
2. `Enter`で検索実行。一致するエントリにカーソルを移動
3. `n`で次の一致、`N`で前の一致へ移動
4. `Esc`で検索を終了

**フィルタ (`f`):**
1. キー入力でステータスバーにフィルタプロンプトを表示（`filter: pattern`）
2. `Enter`でフィルタ適用。一致しないエントリを非表示にする
3. `Esc`でフィルタを解除し、全エントリを再表示

## 6. データモデル

### 構造体間の関係図

```
App (internal/ui)
├── SourcePane  *pane.Pane              (左ペイン)
├── DestPane    *pane.Pane              (右ペイン)
├── YankBuffer  *pane.YankBuffer
├── Selector    selector.CommandRunner
├── FocusLeft   bool
├── Status      string
└── ExitReason  ExitReason

Pane (internal/pane)
├── Dir         string
├── Entries     []fs.Entry
├── Cursor      int
├── Selected    map[int]bool
└── FS          fs.FileSystem (インターフェース)

Entry (internal/fs)
├── Name        string
└── IsDir       bool

YankBuffer (internal/pane)
├── Entries     []string  (フルパス)
└── SrcDir      string
```

### App（`internal/ui` パッケージ）

アプリケーション全体の状態を保持するトップレベル構造体。`internal/ui`パッケージに配置する。

```go
type ExitReason int

const (
    ExitReasonNone       ExitReason = iota

type App struct {
```

### Pane（`internal/pane` パッケージ）

各ペインの状態を管理する構造体。gocuiに依存しない。

```go
type Pane struct {
    Dir      string       // 現在のディレクトリの絶対パス
    Entries  []fs.Entry   // 現在のディレクトリのエントリ一覧
    Cursor   int          // カーソル位置（0始まり）
    Selected map[int]bool // 選択中のエントリのインデックス
    FS       fs.FileSystem // ファイルシステム操作のインターフェース
}
```

### Entry（`internal/fs` パッケージ）

ファイル/ディレクトリ1つを表す構造体。`FileSystem`インターフェースと同じ`internal/fs`パッケージに配置する。

```go
type Entry struct {
    Name  string // ファイル名（ディレクトリ名）
    IsDir bool   // ディレクトリならtrue
}
```

### YankBuffer（`internal/pane` パッケージ）

ヤンクしたエントリを保持する構造体。`Pane`と同じ`internal/pane`パッケージに配置する。

```go
type YankBuffer struct {
    Entries []string // ヤンクしたエントリのフルパス一覧
    SrcDir  string   // ヤンク元のディレクトリパス
}
```

### FileSystem インターフェース（`internal/fs` パッケージ）

ファイルシステム操作を抽象化するインターフェース。`internal/fs`パッケージに定義する。`internal/pane`パッケージがこのインターフェースに依存する（`pane` → `fs` の依存方向）。テスト時にモックを注入できる。

```go
type FileSystem interface {
    // ReadDir はディレクトリのエントリ一覧を返す
    ReadDir(path string) ([]Entry, error)
    // Copy はsrcをdstにコピーする。ディレクトリの場合は再帰的にコピーする
    Copy(src, dst string) error
    // Remove はファイル/ディレクトリを完全削除する
    Remove(path string) error
    // Trash はファイル/ディレクトリをOS標準のゴミ箱に移動する
    Trash(path string) error
    // Rename はファイル/ディレクトリをリネームする
    Rename(oldPath, newPath string) error
    // Create はファイルまたはディレクトリを作成する。isDirがtrueならディレクトリを作成する
    Create(path string, isDir bool) error
}
```

### CommandRunner インターフェース（`internal/selector` パッケージ）

外部コマンド（ghq, fzf）の実行を抽象化するインターフェース。`internal/selector`パッケージに定義する。`internal/ui`パッケージの`App`構造体がこのインターフェースを保持する。テスト時にモックを注入できる。

```go
type CommandRunner interface {
    // SelectRepository は ghq list | fzf を実行し、選択されたリポジトリのフルパスを返す。
    // ユーザーがキャンセルした場合は空文字列とnilを返す。
    SelectRepository() (string, error)
}
```
